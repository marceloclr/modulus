# 1. REGRA FUNDAMENTAL

NÃO destrua o sistema existente.

Antes de modificar qualquer coisa:

1. faça auditoria do código existente;
2. identifique todos os arquivos;
3. identifique funções;
4. identifique modelos de dados;
5. identifique regras geométricas;
6. identifique regras de geração;
7. identifique cálculos;
8. identifique componentes de interface;
9. identifique dependências;
10. identifique funcionalidades já existentes;
11. identifique bugs;
12. identifique inconsistências;
13. identifique código duplicado;
14. identifique regras hard-coded;
15. identifique pontos que impedem futura expansão.

Não reescreva o sistema simplesmente porque uma arquitetura diferente parece mais elegante.

Preserve tudo aquilo que funciona.

**ABNT NBR 9050:2020 — Versão Corrigida:2021**

Status: em vigor, confirmada em 11/12/2025.

## REGRA DE OURO DO SISTEMA

**Nenhum parâmetro urbanístico, arquitetônico, estrutural, de acessibilidade, segurança contra incêndio ou desempenho deve ser inventado pela IA.**

Se o parâmetro puder ser confirmado:

**usar o parâmetro + fonte + artigo/item + data de verificação.**

Se houver dúvida:

**marcar como NÃO VERIFICADO.**

Se houver conflito:

**mostrar o conflito.**

Se a informação for apenas uma recomendação de projeto:

**marcar como RECOMENDAÇÃO.**

Se for uma estimativa:

**marcar como ESTIMATIVA.**

Se for uma regra legal:

**marcar como REQUISITO LEGAL.**

Se for uma norma técnica:

**marcar como REQUISITO NORMATIVO.**

Dessa forma, o MODULUS não confundirá legislação, norma técnica, cálculo de engenharia, heurística arquitetônica e preferência do usuário.



Não considere o projeto encerrado enquanto todas as fases acima não forem implementadas ou explicitamente marcadas como futuras.
